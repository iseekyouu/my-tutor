# Словарик — тренажёр слов

Весь стек на Bun: сервер `Bun.serve`, база `bun:sqlite` (файл `data.db`),
фронтенд на React собирает и отдаёт сам Bun, без Vite.

## Запуск

```bash
bun install
bun run dev      # разработка с hot reload: http://localhost:3000
bun run start    # продакшен-режим
bun test         # тесты базы и проверки ответов
bun run typecheck
```

Переменные окружения:
- `PORT` — порт (по умолчанию 3000)
- `DB_PATH` — путь к файлу базы (по умолчанию `data.db` в папке проекта)

Сервер слушает `0.0.0.0`, поэтому с телефона в той же Wi-Fi сети он открывается
по `http://<IP-компьютера>:3000`.

Бэкап словаря: скопировать `data.db` (при остановленном сервере) или
сделать «Экспорт» в интерфейсе.

## Как пользоваться

1. Добавьте слова: слово, русский перевод и/или английский (нужен хотя бы один перевод),
   по одному или списком — по строке `слово - перевод - english`
   (`слово - перевод` без английского, `слово - - english` без русского).
   Несколько вариантов перевода — через запятую: `дом, здание`.
   Дубли не добавляются: одинаковым считается слово без учёта регистра, пробелов и
   черты среднего тона (`nāam` = `naam`; `náam` и `nàam` — разные). При вводе
   появится предупреждение, а при добавлении списком/импорте дубли пропускаются
   (с итогом «добавлено N, пропущено дублей M»).
2. Под полем слова — таблица гласных транслитерации (a e i o u) с пятью тонами:
   средний, низкий, нисходящий, высокий, восходящий — `ā à â á ǎ`.
   При проверке ответа `ā` и `a` (средний тон с чертой и без) считаются одинаковыми.
   Кнопка вставляет букву в позицию курсора: `n` + `á` + `am` → `náam`.
   Кнопка «тон» прячет таблицу. У полей с русским переводом таблицы нет.
3. Теги — группы слов («еда», «урок 3»). В поле «Теги» Enter или запятая превращают
   набранное в тег, подсказки — из уже существующих. После добавления слова теги в форме
   остаются (удобно вводить группу подряд) и добавляются ко всем словам из «Добавить списком».
   Над словарём — ряд тегов: клик оставляет только слова с этим тегом, и «Начать обучение»
   тренирует только их. Клик по тегу у слова — тот же фильтр.
4. «Начать обучение» — слова идут в случайном порядке. Enter — проверить / дальше.
   Засчитывается любой перевод — русский или английский.
   «Показать ответ» засчитывается как ошибка.
5. «Сбросить счётчики» в шапке словаря обнуляет успехи/неудачи у показанных слов
   (у всех или у выбранного тега), после подтверждения.
6. После последнего слова или «Стоп» — статистика и список слов на повторение.
   Итоги сохраняются на сервере: у каждого слова копятся успехи/неудачи.

Настройки (направление, «Учитывать тоны») хранятся локально на устройстве.

## API

| Метод | Путь | Тело | Ответ |
|---|---|---|---|
| GET | `/api/words` | — | все слова |
| POST | `/api/words` | `{word, translation?, english?, tags?}` или массив | созданные слова (одно слово-дубль → 409, в массиве дубли пропускаются) |
| PUT | `/api/words/:id` | `{word, translation?, english?, tags?}` | слово (дубль другого слова → 409) |
| DELETE | `/api/words/:id` | — | `{ok: true}` |
| POST | `/api/reset` | `{ids: number[]}` | все слова (у этих — ok/fail обнулены) |
| POST | `/api/results` | `[{id, success}]` | все слова с обновлённой статистикой |

`translation` — русский перевод, `english` — английский; нужен хотя бы один из них.
`tags` — массив строк (хранятся в нижнем регистре); если в PUT его нет, теги не меняются.
Старая база при запуске сама получает колонки `english` и `tags`.

CORS открыт, чтобы к API могло ходить мобильное приложение.

## Структура

- `server/index.ts` — HTTP-сервер и маршруты
- `server/db.ts` — схема SQLite и запросы
- `server/db.test.ts` — тесты
- `src/api.ts` — клиент API
- `src/lib.ts` — типы, проверка ответа (нормализация Unicode, тоны)
- `src/TagInput.tsx` — поле тегов
- `src/ToneInput.tsx` — поле ввода с таблицей гласных с тонами
- `src/Dictionary.tsx`, `src/Training.tsx`, `src/Stats.tsx` — экраны

## Деплой на Fly.io

Конфигурация — `Dockerfile` и `fly.toml` (регион `sin`, Сингапур). База SQLite лежит
на постоянном томе `/data`, поэтому машина должна быть ровно одна.

Один раз:

```bash
brew install flyctl && fly auth login
fly volumes create data --size 1 --region sin   # диск под базу
```

Каждый деплой:

```bash
fly deploy
fly scale count 1     # после первого деплоя: Fly по умолчанию создаёт две машины
```

Сайт — `https://my-tutor.fly.dev`. Доступ открыт всем, кто знает адрес.
Перенести локальный словарь: «Экспорт» здесь → «Импорт» на сайте. Бэкап базы с сервера: `fly ssh sftp get /data/data.db`.

## Следующий шаг: Android

Обернуть фронтенд в Capacitor; приложение ходит к этому же серверу:

```bash
bun add @capacitor/core @capacitor/android && bun add -d @capacitor/cli
bunx cap init Словарик com.example.slovarik --web-dir dist
PUBLIC_API_URL=http://<IP-компьютера>:3000 bun run build
bunx cap add android && bunx cap sync && bunx cap open android
```

Для HTTP (не HTTPS) в Android нужно разрешить cleartext-трафик
(`android:usesCleartextTraffic="true"` или `server.cleartext` в capacitor.config).
